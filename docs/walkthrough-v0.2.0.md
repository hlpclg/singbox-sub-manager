# v0.2.0 实施演练与总结

v0.2.0 (基础稳定性) 阶段的功能实现已经完成，等待集成验证。本篇为您总结本次实现的稳定性保障机制。

## 主要实施成果

### 1. 标准化目录与防覆盖
- **配置与密钥收束**：所有用户级的敏感数据（`nodes.conf`、`config.env`、`certs/`）和日志（`installer.log`）均遵循 Linux 标准存放于 `/etc/singbox-sub-manager/` 和 `/var/log/singbox-sub-manager/`。
- **首次真实生成**：`nodes.conf` 只在首次安装时由真实数据初始化（并添加 `# schema-version: 1` 和 `600` 权限），再次运行**绝不覆盖**。
- **证书复用**：`certs/server.crt` 如果存在且校验通过，将被复用。如果证书文件已损坏且非初始化安装，安装进程将会终止并报错。

### 2. 精准原子写入与回滚
- **临时生成校验机制**：所有的修改都将在目标目录生成 `mktemp` 临时文件，并通过对应的 `sing-box check` 与 `caddy validate` 校验。
- **单文件备份**：合法并替换之前，将自动生成 `.previous` 备份（如 `.config.json.previous`）。
- **进程重载安全回滚**：当 `caddy reload` 或 `sing-box restart` 无法正常提供服务时，脚本立即捕捉失败信号并将 `.previous` 逆向恢复。

### 3. 日志与信息脱敏
- **脱敏日志策略落地**：剔除了容易泄露信息的 `tee + sed` 操作。核心安装动作完全不再对密码与私钥使用全局变量或 `echo`，`Token` 信息在日志中强制采取掩码记录（例如 `f0e8****de11`），保障服务器被入侵后的审计安全。

### 4. 端口精准检测
- **避免服务互斥报错**：安装脚本正确识别当前的 TCP/UDP 占用。TCP 80/443 被 Caddy 占用属于豁免，UDP 443 被 sing-box 占用属于豁免。如果有其他程序占用，则会在控制台明文提示 PID 信息并终止安装。

### 5. `proxyctl validate`
- `proxyctl` 工具现已增加深度的配置有效性校验，除了节点合法性验证外，还能够检验生成的 `clash.yaml` 本身是否为严谨的 YAML 结构，确保底层生成代码不出错。

### 6. 旧系统数据平滑迁移
安装脚本将自动侦测 `/etc/proxy-state/` 等旧路径并在确保其有效时进行迁移。旧配置迁移完毕不会立即删除，只做终端告知以保证版本降级的可行性。

## 后续验证建议

目前代码已合并至 `v0.2.0` 本地分支，并附带了对应的 `.github/workflows/ci.yml`。
您可以将此分支 Push 到远端以触发 ShellCheck 和 Go Test。
建议您在一台测试机上拉取该分支，验证旧环境的无缝迁移与原子替换失败回滚的表现，如完全符合预期，我们即可进入下一阶段。

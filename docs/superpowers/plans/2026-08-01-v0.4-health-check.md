# v0.4 Health Check (local) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` or `superpowers:executing-plans`. Execute one Task at a time. Every Task requires TDD, a separate commit, specification review, and code-quality review.

**Goal:** Add `proxyctl health`, a read-only health check for the local subscription-center host with stable text/JSON output and documented exit codes.

**Architecture:** `internal/health` owns check contracts, scheduling, configuration resolution, checks, aggregation, and rendering. `cmd/proxyctl` only parses CLI arguments and orchestrates the package. Local checks run serially; DNS/HTTPS/TLS checks run concurrently with bounded concurrency and cooperative context cancellation.

**Tech Stack:** Go 1.22 standard library only. No new dependencies and no edits to `go.mod` or `go.sum`.

If a Task conflicts with an upper-level requirement, two requirements cannot both be satisfied, or an invariant is ambiguous, stop and report the conflict. Do not copy an implementation from this plan, weaken a test, or silently choose one interpretation.

## Global execution constraints

- This plan defines contracts and acceptance criteria, not production implementations. Exact public APIs and stable protocol fields are contractual; internal helpers are implementation choices.
- Use TDD: add the smallest failing test, run it and record the expected failure, implement the minimum behavior, then run the focused and regression suites.
- Any path that may block, perform external I/O, or create a goroutine must cover success, failure, cancellation, and timeout where applicable. When cancellation is not available in the Go standard library for a small synchronous local syscall/read, document why it is not applicable and test the injectable boundary instead.
- `Check.Run` and all injected blocking seams that accept a context must honor cancellation and return promptly.
- A function must not return while leaving a goroutine it owns running. Concurrency slots remain owned until the associated operation exits.
- Concurrency and lifecycle invariants require deterministic synchronization/counter tests. `go test -race` is additional evidence only.
- No test may depend on real systemd, Caddy, sing-box, public DNS, public network access, GitHub, or fixed host ports.
- Never output or log a password, OBFS password, subscription token, or full subscription URL, including error paths and verbose output.
- Do not modify, stage, or delete pre-existing user changes. Record the Git baseline before each Task.
- A Task is complete only after its focused tests and the common gate pass, its expected files are committed, and the worktree contains no new uncommitted changes from that Task.

### Task 2: Runner, overall timeout, and bounded concurrency

**Files:**

- Create: `internal/health/runner.go`
- Test: `internal/health/runner_test.go`
- Modify only if required by the contract: `internal/health/check.go`

**Contract:**

- Export `RunAll(ctx, cfg, checks, concurrentIDs) []Result`.
- Return results in the same order as `checks`.
- Run local checks serially in slice order while concurrent checks may overlap them.
- Never run more than four concurrent-classified checks at once.
- Enforce the overall deadline through cooperative cancellation. Checks not started or not completed by the deadline report `fail` with message `timeout`.
- Do not create a wrapper goroutine that can outlive `RunAll`. A `Check.Run` implementation that ignores context violates the interface contract; Go cannot forcibly terminate it.
- A waiting concurrent check must stop waiting when the context is cancelled. A semaphore slot is released only after the associated `Check.Run` returns.
- Every result, including timeout-before-start, contains ID, name, status, message, and duration.

**Deterministic acceptance tests:**

- Preserve order and status for mixed serial/concurrent inputs.
- Reach exactly four active concurrent checks and never exceed four.
- Use eight context-aware blocking checks and a short overall timeout; assert every result is `timeout`, all started checks observe cancellation, active count returns to zero, and `RunAll` returns within a generous bounded interval.
- Prove queued checks do not begin work after cancellation.
- Run the focused suite repeatedly and with `-race`.

**Workflow:**

- [ ] Add the lifecycle/concurrency tests and confirm they fail for the unsafe implementation.
- [ ] Implement the scheduler without prescribing internal helper names.
- [ ] Run `go test -count=20 ./internal/health/ -run RunAll` and `go test -race -count=1 ./internal/health/`.
- [ ] Run the common gate.
- [ ] Commit with message `feat(health): concurrent runner with overall timeout cap` or a narrowly scoped corrective message when repairing an existing commit.

### Task 4: UDP/TCP port checks

**Files:**

- Create: `internal/health/port.go`
- Test: `internal/health/port_test.go`

**Contract:**

- `port.udp443` parses injected `/proc/net/udp`-style paths and passes when local port hex `01BB` exists in IPv4 or IPv6 data. It only reports socket-listening state, never Hysteria2 health.
- Missing/unreadable proc sources and no listener are distinct tested failures without leaking host paths beyond the approved diagnostic message.
- `port.tcp443` and `port.tcp80` use `net.Dialer.DialContext` with the configured TCP timeout and default loopback addresses.
- Connections are always closed.
- Local proc reads use small injected pseudo-files; stdlib file reads are not cancellable. Check context before each read and document this bounded local-I/O exception.

**Acceptance tests:**

- UDP IPv4 pass, UDP IPv6 pass, no 443, malformed rows, missing sources, unreadable/error source.
- TCP reachable, refused, context timeout/cancellation, default/injected address selection.
- TCP tests use ephemeral listeners only.

**Workflow:**

- [ ] Add focused failing tests and confirm RED.
- [ ] Implement the checks from the contract.
- [ ] Run focused tests, `-race`, and the common gate.
- [ ] Commit with message `feat(health): UDP/TCP port checks`.

### Task 6: Loopback HTTPS, TLS certificate, and expiry checks

**Files:**

- Create: `internal/health/tls.go`
- Test: `internal/health/tls_test.go`

**Contract:**

- Stable IDs: `http.subscription`, `tls.certificate`, `tls.expiry`.
- Always dial the configured/default loopback TLS address while presenting the resolved domain as SNI and HTTP Host.
- HTTPS uses GET, requires HTTP 200, and applies both request and dial timeouts.
- TLS verifies chain, hostname, and validity against injected/system roots.
- Expiry is WARN below the specification window and PASS otherwise; handshake/validation failure is FAIL.
- Empty domain and unavailable token follow the specification's cascade behavior.
- Close every response body, transport idle connection, and TLS connection.
- No message may include token, password, or full URL.

**Acceptance tests:**

- Use local ephemeral TLS servers and generated test certificates only.
- HTTP 200, non-200, GET-not-HEAD, token cascade, domain absence, timeout/cancellation.
- Certificate valid, hostname mismatch, untrusted chain, expired, handshake failure, timeout/cancellation.
- Expiry far, near threshold, exactly at boundary with controlled time where practical, and expired.
- Secret-redaction assertions for every error path.

**Workflow:**

- [ ] Add local-server/certificate tests and confirm RED.
- [ ] Implement loopback transport and checks.

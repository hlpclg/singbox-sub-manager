# v0.7 备份、升级与回滚 — 实施计划

> **Goal:** 实现可校验、可安全恢复且能在升级失败时同时回滚配置与 `proxyctl` 二进制的 v0.7 备份流程。
>
> **Architecture:** `internal/backup` 负责可注入根目录下的归档、预检、校验和原子文件恢复；CLI 负责锁、服务复检与保留策略；安装脚本负责升级会话及二进制暂存/恢复。所有跨进程协调通过有界锁等待和会话元数据完成。
>
> **Tech Stack:** Go 1.22、POSIX tar/gzip、Shell、既有 `monitor.FileLock` 与服务控制器。
>
> **Spec:** `docs/superpowers/specs/2026-08-17-v0.7-backup-upgrade-rollback-design.md`

**Global Constraints（优先于各 Task，Task 不得覆盖）**

## Task 1: 备份打包（internal/backup 归档与清单）

**Files:**
- Create: `internal/backup/archive.go`, `internal/backup/archive_test.go`
- Create: `internal/backup/manifest.go`, `internal/backup/manifest_test.go`

**契约：**

- `Create(ctx context.Context, opts CreateOptions) (Manifest, error)`：按设计文档第 4 节的固定路径集合打包为 `.tar.gz`；`/etc/singbox-sub-manager/**` 是递归树规则，遍历其全部后代普通文件，其他列出的路径是显式单文件规则。显式路径不存在记入 `manifest.Skipped`。
- `Manifest{SchemaVersion int, CreatedAt time.Time, ProxyctlVersion string, Files []FileEntry, Skipped []string, SkippedReasons map[string]string}`，`FileEntry{Path, SHA256 string, Mode fs.FileMode, UID, GID uint32}`；UID/GID 是打包时源文件的数值属主，用于恢复 Caddy 的 `root:caddy 0640` 等真实权限模型。
- `CreateOptions` 至少包含源根目录 `SourceRoot`（生产为 `/`，测试为临时目录）、备份目录、`--out` 覆盖路径、当前 `proxyctl` 版本注入（用于测试可控）、时钟注入（`Now func() time.Time`）；清单中的逻辑路径相对 `SourceRoot` 记录，归档输出路径与源根目录隔离。
- 归档写入采用同目录临时文件 + `fsync` + 原子 `rename`；失败时不得残留可被误认成功归档的最终文件名。
- 源端遍历一律使用 `Lstat`：普通且 `st_nlink == 1` 的文件才进入 `Files`；硬链接通过 `Stat_t.Nlink` 判定，不能仅依赖 `Lstat` 的类型位。递归树内的符号链接、硬链接、设备/套接字/FIFO 和空目录不得跟随或写入 tar，而是记入 `Skipped` 与稳定原因（`unsupported_source_type` 或 `empty_directory`）并继续遍历其余条目；显式单文件遇到上述非普通类型则返回 `ErrUnsupportedSourceType`，整个备份失败且不生成最终归档。显式路径与递归树根自身的 `ENOENT` 均进入 `Skipped`，原因 `not_found`（2026-09-08 用户裁决：树根缺失必须可见，与设计文档第 4 节一致；修订前本行为“仅显式路径”）。
- 自动归档名固定为 `backup-YYYYMMDDTHHMMSSZ.tar.gz`；同秒冲突从 `-1` 起递增，即 `backup-YYYYMMDDTHHMMSSZ-<positive-int>.tar.gz`。仅此正则 `^backup-[0-9]{8}T[0-9]{6}Z(?:-[1-9][0-9]*)?\\.tar\\.gz$` 属于系统创建归档；以 `O_EXCL` 保留候选名，冲突时重试下一个后缀。`--out` 不适用该命名或保留策略。

**不变量：**

- 归档内每个文件的 SHA-256 与打包时读取内容一致（写入清单前读、写入归档前不得被修改，或采用读取一次后同时用于内容和摘要）。
- 缺失路径不导致整体失败，只进入 `Skipped`。
- 归档文件名冲突（同一秒内多次调用）不得互相覆盖或产生半成品文件。
- 默认备份目录（`/var/lib/singbox-sub-manager/backups`）创建时权限为 `0700`；归档文件权限为 `0600`；`Create` 不得依赖调用方 umask 达到该权限，必须显式设置。归档内文件条目的 tar header 记录原始 `Mode` 与 UID/GID，恢复时不得放宽；不得把所有文件错误压缩为 `0600`。`/etc/caddy/Caddyfile` 的 `root:caddy 0640` 必须可无损往返；归档本身和备份目录仍是私有的。递归树可能包含私钥（如 `certs/server.key`），README 必须说明归档含敏感材料及其保存责任。
- 归档格式固定为恰好一个 `manifest.json` 加上清单 `Files` 中的普通文件条目；不写入目录条目，`Skipped` 不生成 tar 条目。恢复时按文件的父路径显式创建目录，空目录不恢复。条目名使用清单的相对逻辑路径，禁止通过绝对路径或工作目录解释路径。

## Task 2: 恢复与校验（internal/backup 恢复路径）

**Files:**
- Create: `internal/backup/restore.go`, `internal/backup/restore_test.go`
- Create: `internal/backup/lock.go`, `internal/backup/lock_test.go`（有界重试锁协调包装）
- Create: `internal/backup/snapshot.go`, `internal/backup/snapshot_test.go`（恢复前映像及逐字节回滚）

**契约：**

- `Verify(ctx context.Context, archivePath string) (Manifest, error)`：解包清单、重新计算每个文件 SHA-256 并与清单比对，`schema_version` 不支持时返回明确错误；接受 `ctx` 以覆盖大归档校验的取消/超时。
- `ReadManifest(ctx context.Context, archivePath string) (Manifest, error)`：只读取并结构校验 `manifest.json`（含路径与 schema），不重算全部 payload 摘要；供 `backup list` 获取版本和时间，失败/取消/超时返回分类错误且零写入。
- **提取安全边界（先于任何写入执行的预检，属于 `Verify` 的一部分或 `Restore` 写入前的强制前置步骤）：**
  - 拒绝清单或 tar 条目中的绝对路径、包含 `..` 的路径穿越、重复路径条目。
  - 拒绝 tar 中的符号链接、硬链接、设备文件等非普通文件/目录条目。
  - 拒绝"清单与 tar 实际内容不一致"的归档：tar 中存在清单未声明的条目，或清单声明的条目在 tar 中缺失，均视为校验失败。
  - 以上任一条件触发时，返回明确的分类错误（区分"路径不安全"与"内容不一致"），且不得有任何文件系统写入（含临时文件）。
- `Restore(ctx context.Context, archivePath string, opts RestoreOptions) (Result, error)`：
  - `RestoreOptions{DryRun bool, DestRoot, SnapshotRoot string, Lock Locker, Lease LockLease, CapturePreimage bool, LockRetryInterval, LockMaxWait time.Duration}`。`DestRoot` 为目标根目录注入点（生产默认 `/`，测试注入临时目录），归档内路径均相对 `DestRoot` 解析；生产 `SnapshotRoot=/var/lib/singbox-sub-manager/restore-snapshots`，不得落在任何备份源树（尤其 `/etc/singbox-sub-manager/**`）内；测试注入临时目录。默认锁参数固定为 `LockRetryInterval=100ms`、`LockMaxWait=30s`，测试可注入。
  - `LockLease` 为已获取锁的可组合租约（仅暴露 `Unlock() error`）；传入 `Lease` 时 `Restore` 不再获取或释放锁，租约所有权归调用方。未传 `Lease` 时才由 `Restore` 用 `Lock` 获取并在返回前释放。
  - `Locker` 接口为 `TryLock() error` / `Unlock() error`（由调用方传入满足该接口的实现，`internal/backup` 不导入 `internal/monitor`，避免循环依赖；Task 3 负责用 `monitor.FileLock` 适配注入）。`Restore` 在写入前必须持有锁；`Locker` 为 `nil` 时视为调用方明确放弃锁协调（仅限测试或未来单机以外场景使用），生产 CLI 路径必须传入。
  - `DryRun=true` 时只计算并返回预览，不获取锁、不写入文件系统。
- `Result{Restored []string, Failed []string, FailureReasons map[string]string, Preview []FileDiff, Preimage *RollbackSnapshot}`：`FailureReasons` 为每个 `Failed` 路径的稳定分类/取消原因；`FileDiff{Path string, Action string /* create|overwrite|unchanged */, OldSHA256, NewSHA256 string}`。非 dry-run 时 `Preview` 为空，`Restored`/`Failed` 按写入结果填充；dry-run 时 `Restored`/`Failed` 为空，`Preview` 给出新旧摘要对比；请求 `CapturePreimage` 时返回 `Preimage`。
- `RollbackSnapshot` 位于 `SnapshotRoot/<transaction-id>`，含原子写入的 `snapshot.json`（路径、存在性、模式、UID/GID、内容摘要、payload 名称）及每个原有文件的逐字节 payload；原本不存在的路径只记录 `Exists=false`，不创建 payload。快照目录 `0700`、元数据/payload `0600`，创建完成后目录 `fsync`；仅在后续重启/复检和必要回滚完成后删除，删除失败须告警并保留可手动恢复的路径。启动一次恢复前清理超过 7 天且不属于活动事务的遗留快照，并把清理失败作为告警，不删除仍供人工排查的最新失败快照。
- `RollbackOptions{DestRoot string, Lease LockLease}`；`DestRoot` 必须与创建映像时一致，`Lease` 必须是调用方已持有的租约，`Rollback` 不会重新获取或释放它。`Rollback(ctx context.Context, snapshot *RollbackSnapshot, opts RollbackOptions) (RollbackResult, error)` 逐项读取并校验快照元数据，原有文件按 payload 逐字节原子恢复，并恢复原 Mode/UID/GID；`Exists=false` 的目标若当前存在则删除新建文件。`RollbackResult{Restored, Deleted, Failed, FailureReasons}` 逐项报告结果。取消/超时立即停止后续项、保留已完成项并在 `FailureReasons` 标明 `context.Canceled`/超时；任一失败不删除快照并返回可识别错误。仅 `Rollback` 成功且调用方确认事务结束后调用 `CleanupSnapshot(ctx, snapshot)` 删除映像，清理失败告警但保留映像。
- 恢复不在本模块内触发服务重启；重启编排属于 Task 3 的 CLI 层职责，`internal/backup` 只负责文件级别的读写、校验和锁协调。

**锁协调契约（`internal/backup/lock.go`）：**

- 提供 `AcquireWithRetry(ctx context.Context, l Locker, interval time.Duration, maxWait time.Duration) (LockLease, error)`：对不支持阻塞等待的 `TryLock`（如 `monitor.FileLock`）做有界轮询封装，不修改 `internal/monitor/lock.go`；成功返回的租约由调用方负责释放。
- 超过 `maxWait` 仍未获取锁时返回可识别的"锁繁忙"错误（区别于其他内部错误）；`ctx` 取消时立即返回 `ctx.Err()`，不再继续轮询。
- 未传入外部租约时，`Restore` 成功获取后必须在所有退出路径（成功、失败、panic 恢复、ctx 取消）上调用 `Unlock`；`Unlock` 失败必须作为结果错误报告。外部租约由 Task 3 在整个事务结束后释放，测试须验证两种所有权模式均不遗留持锁进程。

**不变量：**

- 校验和不匹配、路径不安全或清单与内容不一致时，`Verify`/`Restore` 拒绝执行且不写入任何文件（含不获取锁）。
- 恢复先为全部目标写同目录临时文件并 `fsync`，仅在全部暂存成功后才依次 `rename` 并 `fsync` 父目录；暂存阶段失败时零目标可见写入且保留 preimage。rename 阶段失败会报告已生效与未生效项，不由 `Restore` 隐式回滚，保留 preimage 交由 Task 3 的事务编排回滚（与设计文档第 5 节一致）。
- `DryRun` 模式下文件系统零写入、零加锁，可通过测试注入的只读文件系统或写入/加锁计数器验证。
- 所有写入路径基于 `DestRoot` 解析后仍须落在 `DestRoot` 内（提取安全边界的第二重防御，即使清单校验已拒绝穿越路径）。

**不变量：**

- 保留策略清理只删除自身创建的、路径匹配归档命名规则的文件，不删除用户放入 `backups/` 目录的其他文件。
- restart-then-recheck 使用与 `internal/monitor` 相同的服务控制器抽象（避免重复实现 `systemctl restart` 调用），但不与 monitor 共享运行时状态或触发 monitor 的失败计数。

## Task 4: install-proxy.sh update/rollback

**Files:**

**契约：**

- 顶层入口须在既有位置参数解析前分流 `install`、`update`、`rollback`：`install` 和省略子命令保持现有域名安装语法与行为；`update` 不要求域名；`rollback` 仅接受 `--to <backup-id>`。把安装主体置于顶层可抽取的 `cmd_install`，新增 `cmd_update`、`cmd_rollback` 及可注入路径、下载器和健康检查的顶层函数，以兼容现有 awk 函数抽取 harness。
- `sudo ./install-proxy.sh update`：
  1. 查询 GitHub Release 最新 tag（复用现有版本查询模式），在替换前以当前二进制探测 `backup --help` 和 `restore --help`。若旧版本（含 v0.6）不支持任一能力，明确报告“本次为仅二进制升级，无法创建/自动回滚配置快照”，继续二进制流程；不得调用不存在的旧命令。
  2. 能力齐全时由当前二进制创建本次专用配置快照并记录路径；任何配置回滚都必须在新二进制仍在位时以其绝对路径执行 `restore`，随后才可恢复旧二进制，避免 v0.6 缺少该子命令而使回滚失效。
  3. 将当前 `${PROXYCTL_BIN}` 与 `${PROXYCTL_BIN}.sha256` 复制（非移动）到 `/var/lib/singbox-sub-manager/updates/<timestamp>/` 的 `proxyctl.previous` 与 `proxyctl.previous.sha256`，分别记录 SHA-256；两者共同构成唯一可信的二进制回滚副本，线上原件保持可执行。
  4. 下载对应架构的 `proxyctl-linux-{amd64,arm64}`，用 Release `checksums.txt` 校验；为新二进制生成与既有安装脚本兼容的 `${PROXYCTL_BIN}.sha256` 内容。
  5. 新二进制和 sidecar 均校验后，以各自同目录临时文件 + `fsync` + `rename` 原子替换 `${PROXYCTL_BIN}`（`0755`）与 `${PROXYCTL_BIN}.sha256`（沿用既有 `0644`）；任一暂存、元数据或替换前校验失败都不得触碰线上对。
  6. 健康检查固定运行新二进制的 `proxyctl health --json`；仅退出码 `0`（Healthy）成功，`1` Unhealthy、`2` Degraded、超时和执行错误都失败。失败时先以新二进制执行该会话快照的配置回滚（若已创建），再校验暂存副本并原子恢复旧二进制和旧 sidecar；任一步失败都保留会话并以非 0 报告不确定状态。
  7. 健康检查成功后将会话标记为成功，但保留最近 1 个成功会话（旧二进制、旧 sidecar、元数据和配置快照）供后续手动 `rollback`；仅在新一次成功 update 使其成为较旧会话时清理。失败和信号中断会话也保留，不作自动删除。
- 升级会话目录创建为 `0700`，暂存二进制、sidecar、SHA-256 记录和会话元数据为 `0600`；会话元数据先写同目录临时文件并 `fsync` 后原子 `rename`，只有元数据落盘成功后才允许替换线上二进制对。
- `sudo ./install-proxy.sh rollback [--to <backup-id>]`：不带参数使用最近一次会话；带 `--to` 使用指定会话或配置快照 ID。存在二进制对时，先用当前（新）二进制执行配置恢复，再校验并原子恢复二进制及其 sidecar；只有配置快照时明确报告“仅回滚配置，二进制未变更”。找不到任何可用快照/会话时明确报错，不做静默无操作。
- 下载失败、校验失败必须在替换二进制之前发现；已下载的临时文件校验失败时删除并保留线上二进制及 sidecar 不变。收到 `SIGINT`/`SIGTERM` 时不得误删已完整落盘的会话；信号测试在子 shell 中执行命令并投递信号。

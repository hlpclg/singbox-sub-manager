# v0.10 Reality 节点安装实施计划

> 执行者：按仓库工作流逐 Task 实施、独立审查、提交和封账。本文只定义契约、验收与提交范围，不提供生产实现代码；不自动启动子代理实施或后续版本工作。

Task-ID：v010-plan；Stage：计划；日期：2026-09-25。

实施业务风险：L2（私钥、root 文件写入、并发一致性和崩溃恢复）；流程复杂度：高（Go/Shell、两个主机角色、两个架构及 systemd）。本轮仅编写计划，不执行实现或真机变更；实施范围依据上述定稿规格。

**目标**：交付独立 Reality 节点生命周期、订阅中心事务化发布、统一节点菜单与 bootstrap 首装/过渡升级。

**架构**：角色与实例状态只读识别；实例生命周期和发布共用一个持久化事务引擎。Go 承担生命周期、恢复、发布和交互，Shell 只负责 bootstrap 与已有入口的互斥保护；复用已有 nodes、render、health/remote 和文件锁机制。

**技术栈**：Go 1.22、Linux openat/flock、systemd、Bash、固定版本 sing-box；保持现有 Darwin 构建门禁。

**规格**：[v0.10 定稿](../specs/2026-09-18-v0.10-reality-node-install-design.md)，基线 `6a98e08b416af4d90be8193c0082ffb59a86b4ca`；代码基线 `main@df3a4f4`。计划开始时分支 `feature/v0.10.0`，工作区及暂存区干净。套件更新草稿不是本计划的实施依据。

**当前状态**：计划已通过独立审查（2026-09-25）；Task 1–14 均未实施。§17.3 可选的无参数主菜单及 `proxyctl status` 整体顺延，本文仅交付必选的 `proxyctl node` 菜单。

## 全局约束

以下约束只在这里定义，各 Task 引用编号，不覆盖或复制。实现者同时阅读定稿规格；本文的测试清单不缩减规格要求。

- G1 范围与兼容：规格 §2–§4、§14.6、§17–§18。仅独立节点机、单实例、IPv4 服务地址；OS 为 Debian 12、Ubuntu 22.04/24.04，架构 amd64/arm64。没有 `proxyctl update/rollback`、套件会话、旧脚本降级防护或归档导入。旧 CRUD 无 `--publish` 的解析、输出及自定义 `--nodes` 语义保持；既有测试不修改、不删除，若无法同时满足则停止报批。
- G2 CLI：规格 §4.5、§8、§10.1、§13。完整解析先于 root 检查、锁、网络或写入；严格模式不补问。新路径退出码 0/1/2/4/5 和修改边界以规格为准；角色行去 stderr，stdout 保持可粘贴；每块恰好一条可执行命令，参数单引号引用，最低版本 `v0.10.0`。旧 CRUD 保持原有退出码，新增锁/遗留事务拒绝为 1。
- G3 资产与兼容：规格 §3、§5–§6。仅管理资产表中的路径，锁文件不属于资产；未知 manifest schema 只读拒绝，动态状态兼容读取与显式事务迁移，不得由 show/bootstrap 迁移。共享 proxyctl、共享 sing-box 和 bootstrap 旧副本不属于实例。
- G4 事务：规格 §7 全部适用。journal 先登记后执行；原语、路径链、目录身份、回滚序列/完成标记、systemd 进度、提交点及墓碑模型统一；未知 journal schema 或篡改只读返回 5。实例和发布不得各写一套恢复协议。
- G5 路径安全：规格 §7.1 与 v0.7.1 §3.3、§6.5。可信根之下逐级 dirfd + O_NOFOLLOW；每次修改前按 journal 当前 dir_ids 复验。禁止直接用字符串路径绕过受管路径访问；保留规格明确的尽力检测边界。
- G6 锁：规格 §11、§12。L1→L2→L3、反序释放，等待各 30/30/10 秒；monitor 保留 TryLock 返回 3。角色复查、反向检查和遗留事务检查在相应持锁区间内；不得重复申请继承的 flock。保留 §11.4 已知旧路径，不声称全局串行。
- G7 生命周期与预算：规格 §9、§13。全部 I/O、外部命令及锁等待可取消、有超时、释放资源；取消后独立回滚预算 120 秒，committed 只向前清理。超时值统一引用规格 §13.2；假时钟验证时间边界，禁止真实等待 10/30/120 秒充当单元测试。
- G8 密钥与网络：规格 §8.1、§9、§16。私钥实时推导公钥；自检 E1/E2/E3 分离；禁止把私钥或原始生产凭据放进日志、夹具或证据。固定 unit 模板与私网/本机地址拒绝策略必须经 Task 1 真实实测，失败停止，不自行放宽。
- G9 发布：规格 §10。默认布局、分节 nodes.conf、非空启用集合；三个文件可恢复、每文件原子，不能宣称双订阅整体原子；发布不产生 .bak，旧 CRUD 仍保留 .bak；回滚以本地状态为成功条件，HTTPS 复验只告警。
- G10 验证与封账：遵守仓库 AGENTS.md 和 docs/agent-workflows。每 Task 先建立验收矩阵，RED→GREEN→规格审查→质量审查→专项门禁→文档→主提交→状态封账，当前 Task 未封账不得开始下一项。涉及锁、取消、进程和资源生命周期的任务接受独立并发审查，race 不替代确定性验证。
- G11 用户文档：行为所属 Task 同步更新规格 §18.2 指定文档；Task 14 仅重组首页和消除重复。任何扩大范围、规格歧义、既有测试必须变化、实测不能满足固定模板，停止受影响任务并报告。

## 验证命令与通用完成步骤

Go 命令只在 Go 1.22 容器运行。实施前记录镜像 digest、`go version` 和环境；开发机可定义以下会话命令（仅测试命令，不是生产实现）：

```bash
g122() {
  docker run --rm -v "$PWD:/src" -w /src golang:1.22-bookworm "$@"
}
```

真实 Linux 权限、flock、进程中断测试在容器内本地文件系统执行；macOS bind mount 不能充当 Linux 文件系统安全证据。可把当前工作树快照复制到容器工作目录，记录对应 Git diff 摘要，并把证据写回。非 root 夹具在 Linux 可写 `/run/lock` 环境运行；若不满足，按 G1 报告，不能改掉或跳过原测试。真实 systemd 门禁使用一次性目标 VM，普通 Docker 容器不能替代。

| 门禁 ID | 命令/要求 |
|---|---|
| V-Go | 各 Task 给出的 `g122 go test -count=1 ...`；选定测试必须存在并实际执行，禁止空匹配算通过 |
| V-Shell | 对本 Task 变化脚本及新增测试执行 `bash -n`、`shellcheck` 和每个对应 `bash tests/test_*.sh`；ShellCheck 使用与 CI 一致的 Ubuntu runner apt 来源，记录 `shellcheck --version` |
| V-Full | `g122 go test -count=1 ./...`；`g122 go test -race -count=1 ./...`；`g122 go vet ./...`；`g122 gofmt -l .`（零输出）；`g122 env GOOS=darwin go build ./...`；执行 ci.yml/release.yml 的全部 Shell 测试及静态检查 |
| V-Git | 提交前 `git diff --check`、`git diff --cached --check`、`git diff --cached --name-only`；提交后 `git status --short`、`git show --stat --oneline HEAD`；无无关改动 |

每 Task 的复选步骤均须完成 G10：写该 Task 的确定性测试并确认 RED（环境故障不是 RED）→实现契约→同组测试 GREEN→独立规格/质量审查→专项门禁→同步文档→V-Full（所有代码、测试、脚本或 workflow Task）→V-Git→独立主提交→立即更新末尾状态表并以 `docs: close v0.10 task N` 封账。纯实测和文档任务以修改前缺失的检查/证据及修改后的检查代替虚假的 RED/GREEN。T1–T13 的主提交/封账前均须完成 V-Full，不能用该 Task 的专项命令替代全仓 race/vet/gofmt/Darwin 构建和适用 Shell 检查；同一最终对象的一次成功 V-Full 可同时满足 Task 门禁和全分支交付，封账只改状态文字时不再重复。后续有代码、测试、依赖、配置、迁移或生成物变化则按影响范围判定失效并补跑，不为流程重复同一有效对象的测试。

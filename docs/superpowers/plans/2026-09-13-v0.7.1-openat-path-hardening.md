# v0.7.1 恢复路径 openat 加固 — 实施计划

> **Goal:** 把 `internal/backup` 在可信根之下的创建、替换、删除和读取改为相对逐级打开的目录 fd，落实设计文档第 3.3 节的无前提保证 1–4 与范围受限的检测能力，公开契约不变。
>
> **Architecture:** 可信根按现状跟随符号链接打开一次；根下名字逐级 `O_NOFOLLOW` 解析；变更前复核祖先链；失败清理按记录、不经复核、不递归；有意删除经复核后按 fd 递归。
>
> **Tech Stack:** Go 1.22、`golang.org/x/sys/unix` v0.25.0。
>
> **Spec:** `docs/superpowers/specs/2026-09-12-v0.7.1-openat-path-hardening-design.md`（2026-09-13 第三轮修订定向复审通过）。下文「设计 §x」均指该文档章节。

> **For agentic workers:** 每个 Task 遵循 `docs/agent-workflows/task-lifecycle.md` 的执行顺序：契约确认 → 验收矩阵 → 最小实施 → 聚焦测试 → 规格符合性审查 → 代码质量审查 → Task 专项门禁 → 计划与用户文档更新 → 主提交 → 状态封账提交 → 下一 Task。

**依据设计**：设计文档第 1–9 节。本计划只描述契约、不变量、验收测试、验证命令和提交范围，不提供生产实现代码，不规定非必要的内部 helper 名称；设计已定义、测试需要引用的三个 hook（`hookAfterOpen`、`hookBeforeMutation`、`hookAfterMkdirat`）属于测试契约，保留其名称与位置。

## 风险与编排

- 业务风险：L2。root 权限下的文件替换与删除，路径安全边界。每个 Task 完成后由未参与实施的审查者独立终审。
- 流程复杂度：单包内部重构，公开契约冻结，5 个 Task 顺序依赖。
- 并发：恢复与回滚在恢复锁租约内单线程执行，本版本不引入 goroutine、channel 或新的锁；不存在需要并发确定性测试的新逻辑。`internal/backup` 的测试 seam 与 umask 均为进程级状态，**本包测试不得使用 `t.Parallel`**（沿用 v0.7 约束）。

## 设计前置实测（2026-09-13）

以下为写计划前在 Go 1.22 容器内做的探针，用于确认设计假设未被推翻，**不是**各 Task 的验收证据：

- 环境：Docker（OrbStack）Linux 内核 `7.0.14-orbstack`，euid 0；`golang.org/x/sys/unix` v0.25.0。
- API：`Fstat`、`Fchmod`、`Fchown`、`AT_REMOVEDIR` 在 `GOOS=linux`、`GOOS=darwin` 下均可编译（关闭设计 §6.1 推迟项）。
- `Openat(O_RDONLY|O_DIRECTORY|O_NOFOLLOW)` 对指向目录的符号链接、指向文件的符号链接、普通文件、悬空符号链接**均返回 `ENOTDIR`**，未观察到 `ELOOP`。
- 打开子目录后将其 `rename` 到根外，再相对该 fd `Openat(O_CREAT|O_EXCL)`：成功，文件落在根外。
- `Fchmodat(dirfd, name, 0700, 0)` 穿过符号链接修改了根外目录权限；带 `AT_SYMLINK_NOFOLLOW` 时返回 `ENOTSUP`，根外权限不变。
- `Unlinkat(…, AT_REMOVEDIR)`：非空目录返回 `ENOTEMPTY`；指向目录的符号链接返回 `ENOTDIR`，链接目标完好。

结论与设计 §3.3、§6.3、§6.4、§6.7 一致，无需回到设计修订。**验证缺口**：该内核不是受支持的生产内核（Ubuntu 22.04 为 5.15，Ubuntu 24.04 为 6.8），errno 细节可能不同；设计 §6.4 的分类不依赖具体 errno，因此不阻塞实施，但各 Task 证据须记录实际内核版本，生产内核上的行为留待发布后真机验证。

## Global Constraints（优先于各 Task，Task 不得覆盖）

1. **契约冻结**：设计 §5 列出的导出函数、结构体与字段、接口、7 个错误哨兵、全部失败原因/跳过原因/预览动作常量、归档与快照格式、权限模型、退出码与 CLI 输出一律不变。任何 Task 需要改动其中一项，停止并报告。
2. **可信根与根下解析**：可信根（`DestRoot`、`SnapshotRoot`、`BackupDir`、`--out` 的父目录）按设计 §3.1、§6.2 解析；可信根之下的名字只能按设计 §6.3 逐级 `O_NOFOLLOW` 解析。迁移完成的路径中不得残留基于完整路径的创建、替换、删除、读取、`Lstat`。
3. **禁止按名字设权限或属主**：不得使用 `Fchmodat(dirfd, name, …)`、`Fchownat(dirfd, name, …)`、`os.Chmod`、`os.Chown` 作用于可信根之下的名字（设计 §6.3）。
4. **目录 mode 与清理责任**：按设计 §6.3 表格逐行执行，无统一默认 mode；`EEXIST` 的目录项不 `Fchmod`、不进入清理列表；快照事务目录必须新建。
5. **复核与例外**：设计 §6.5 列出的变更与读取调用前执行祖先链复核；设计 §6.7 定义的失败清理不经复核、按记录删除、不递归；设计 §6.6 的有意删除经复核。
6. **表述约束**：代码注释、测试名、错误文案与文档不得把祖先链复核、身份比对表述为保证；不得声称 `Mkdirat` 成功证明后续 fd 属于本次创建（设计 §3.3、§6.3）。
7. **测试 seam**：三个 hook 按设计 §6.5 的位置实现，生产构建为空操作。引入理由：TOCTOU 类不变量依赖「在两次系统调用之间改变文件系统」，现有结构没有可控注入点，仅靠外部并发无法得到确定性结果；较小的改动（例如只在测试中并发替换）无法稳定命中窗口。行为等价性由既有测试原样通过与 §7.3 跨版本测试证明。

- Modify: `.github/workflows/ci.yml`（增加 `GOOS=darwin go build ./...` 步骤）

**契约：**

- 可信根打开：设计 §6.2。需要创建时沿用跟随符号链接的创建方式；给定 mode 时对根 fd 执行 `Fchmod`。
- 根下逐级打开与目录创建：设计 §6.3，包括按用途显式传入 mode、「允许既有」与「必须新建」两种策略、`EEXIST` 语义、第 1–4 步顺序、`Mkdirat` 成功不证明后续 fd 归属。
- 错误分类：设计 §6.4 表格，集中于单一实现，供后续 Task 复用。
- 祖先链复核：设计 §6.5，逐层比较 `(st_dev, st_ino)`，不一致、缺失或打开失败返回 `ErrUnsafePath`。
- 测试 seam：`hookAfterOpen`、`hookBeforeMutation`、`hookAfterMkdirat`，位置与设计 §6.5 流程一致，生产为空操作。
- 本 Task **不改变**任何公开入口的行为；新能力只被本 Task 的测试直接驱动。
- 替代测试 R1–R3：为 Task 4 删除 `TestResolveUnderRoot_KeepsPathsInside` 预先落地等价的行为验收（Global Constraints 第 9 条「测试替换」）。原测试断言与替代关系：

| 原断言 | 原测试行为 | 替代测试 | 等价的行为验收 | 精确变异 | 变异后必然失败的原因 |
|---|---|---|---|---|---|
| ① `../escape` 返回 `ErrUnsafePath` | 穿越路径被拒绝 | R1 | 以「允许创建」策略驱动根下解析：逻辑路径 `../escape` 返回 `ErrUnsafePath`（原输入原样保留）；另以 `../escape/file` 驱动，返回 `ErrUnsafePath`，且可信根的父目录中不出现名为 `escape` 的目录项（`escape` 在该输入中是需要创建的父目录，使副作用可观察） | 从根下解析入口删除逻辑路径校验 | `../escape` 不再返回 `ErrUnsafePath`；`../escape/file` 经 `..` 逐级解析，在根的父目录创建 `escape` |
| ② `/etc/passwd` 返回 `ErrUnsafePath` | 绝对路径被拒绝 | R2 | 以「只解析不创建」驱动，逻辑路径 `/etc/passwd`：返回 `ErrUnsafePath`，不返回任何已打开对象 | 同上 | 返回结果不再是 `ErrUnsafePath`：视实现方式，或把绝对路径交给 `Openat`（忽略 dirfd）而解析到真实 `/etc`，或以空分量等非安全类错误失败；两种都不满足断言 |
| ③ `etc/caddy/Caddyfile` 解析为 `filepath.Join(root, "etc/caddy/Caddyfile")` | 合法路径解析到指定根之下的该位置 | R3 | 在测试根中预置 `etc/caddy/Caddyfile`；经根下解析打开该对象，其 `(st_dev, st_ino)` 等于 `os.Stat(filepath.Join(root, "etc/caddy/Caddyfile"))` 的结果 | 解析改为相对可信根的父目录（或其他错误基准）起步 | 打开的对象不是根下该位置的文件，身份不一致或解析失败 |

  fd 化后解析不再返回路径字符串，原断言 ③ 的「路径相等」无法原样保留，R3 以对象身份相等验收同一行为：合法逻辑路径解析到指定根之下的对应位置。

**不变量：**

- 根下任一分量为符号链接时不被跟随，按设计 §6.4 返回 `ErrUnsafePath`；普通文件充当父目录时返回非安全类错误。
- 只有本次 `Mkdirat` 成功的目录被 `Fchmod` 并记录；`EEXIST` 的目录项既不 `Fchmod` 也不记录。
- 「必须新建」策略下 `EEXIST` 返回错误，既有目录的权限、内容与存在性不变。
- 所有 fd 在成功、失败、取消路径上配对关闭。

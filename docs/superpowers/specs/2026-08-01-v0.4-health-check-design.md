# v0.4 健康检查（本机）— 设计文档

- 日期：2026-08-01
- 版本目标：v0.4.0
- 范围：`proxyctl health` — 订阅中心**本机**健康检查（只读、只报告）。远程节点探测不在本版。

## 背景与范围划分

部署模型（见 README「架构」）：

- 每台节点服务器运行 sing-box（Hysteria2 / UDP 443）。
- 其中一台同时是「订阅中心」，运行 Caddy，对外提供 `clash.yaml` / `sr.txt`。
- `proxyctl` 运行在订阅中心这台机器上；`nodes.conf` 里列出的节点多在**其他机器**上。

因此 plan.md 第六阶段列出的「健康检查」实为两类，复杂度差一个数量级：

| 类别 | 检查什么 | 方式 | 风险 |
|---|---|---|---|
| **A. 订阅中心本机健康** | Caddy/sing-box 服务、端口、配置、订阅文件、HTTPS、TLS 证书、DNS、磁盘 | shell 命令编排 + 本地 socket/文件 + loopback 网络 | 低 |
| **B. 远程节点健康** | `nodes.conf` 每个远程 HY2 端点是否可用 | QUIC/UDP + 认证 + obfs 握手 | 高 |

**v0.4 只做 A。** B 顺延到 v0.5，并明确分两级：

```text
v0.5-a：远程 UDP/QUIC 可达性初筛
v0.5-b：完整 Hysteria2 认证握手与实际代理请求
```

其中 **v0.5-b 才能作为自动禁用节点的依据**。仅凭 ping、UDP socket 或端口扫描，不能判断 HY2 节点健康。

## 目标 / 非目标

**目标**：让运维一条命令看清订阅中心是否在正常提供服务，为后续监控（systemd timer）提供稳定的机器可解析输出。

**非目标（v0.4 明确不做）**：

- `proxyctl repair` / `proxyctl diagnose`
- 自动禁用节点、自动重启服务
- 任何修改系统状态的动作
- 远程节点探测（v0.5）
- 「系统时间」检查（无干净、无外部依赖的本地方法；不让实施方自创土法）
- 「DNS 解析 IP vs 公网 IP 对比」（外部依赖 + 隐私泄漏 + 抖动 WARN；只保留纯 DNS 解析检查）

**健康检查只能读取和报告，不修改系统状态。**

## 命令

```bash
proxyctl health
proxyctl health --json
proxyctl health --verbose
proxyctl health --domain sub.example.com   # 显式覆盖域名来源
```

CLI 路由在 `cmd/proxyctl/main.go` 增加 `case "health"`（与现有 `node` / `subscription` 一致）。

## 检查项目（15 项）

| # | 检查 | 方法 | 成功标准 | 失败语义 |
|---|---|---|---|---|
| 1 | sing-box 服务 | `systemctl is-active sing-box` | 输出 `active` | 非 active → FAIL |
| 2 | Caddy 服务 | `systemctl is-active caddy` | 输出 `active` | 非 active → FAIL |
| 3 | UDP 443 监听 | 读 `/proc/net/udp` + `/proc/net/udp6` | 本地端口 443 存在于监听集合 | 缺失 → FAIL |
| 4 | TCP 443 监听 | TCP connect `127.0.0.1:443` | 建连成功 | 失败 → FAIL |
| 5 | TCP 80 监听 | TCP connect `127.0.0.1:80` | 建连成功 | 失败 → FAIL |
| 6 | sing-box 配置 | `sing-box check -c /etc/sing-box/config.json` | 退出码 0 | 二进制缺失→WARN；存在但非法→FAIL |
| 7 | Caddy 配置 | `caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile` | 退出码 0 | 二进制缺失→WARN；存在但非法→FAIL |
| 8 | 订阅 token | 读 `/var/lib/singbox-sub-manager/token`（旧 `/etc/proxy-sub-token` 仅回退） | 存在且匹配 `^[A-Za-z0-9_-]{16,128}$` | 缺失/格式非法 → FAIL |
| 9 | clash.yaml | 检查 `/var/www/proxy-sub/<token>/clash.yaml` | 存在、非空、可读 | 否则 FAIL |
| 10 | sr.txt | 检查 `/var/www/proxy-sub/<token>/sr.txt` | 存在、非空、可读 | 否则 FAIL |
| 11 | HTTPS 订阅 | HTTP **GET**（loopback，见下）`https://<domain>/<token>/clash.yaml` | 200（不能只用 HEAD） | 否则 FAIL |
| 12 | TLS 证书 | TLS handshake（loopback，SNI=域名） | 域名匹配且未过期 | 否则 FAIL |
| 13 | 证书剩余时间 | 解析 `NotAfter` | ≥ 14 天 | < 14 天 → WARN |
| 14 | DNS | `net.LookupHost(domain)` | 至少解析出一个 IP | 否则 FAIL |
| 15 | 磁盘空间 | `statfs`（订阅根目录所在文件系统） | 剩余 ≥ 500 MB | < 500 MB → WARN |

### 关键实现约束

- **UDP 443（#3）宽松判定**：只判断本地端口 443 是否在 UDP 监听集合中，**不**强行关联 sing-box 进程（socket inode → pid 关联脆弱、需 root、易误判）。稳、免 root、跨发行版。
- **HTTPS / TLS / 证书（#11–13）走 loopback**：拨 `127.0.0.1:443`，TLS `ServerName` 设为域名（等价于 install-proxy.sh 冒烟测试里的 `curl --resolve $DOMAIN:443:127.0.0.1`）。这样避开某些云的 hairpin NAT 把「本机访问自己公网 IP」误判成 FAIL，同时照样验证 Caddy 返回 200 且证书对域名有效。三项可共用一次 loopback 连接。
- **DNS（#14）走真实解析**：独立一项，验证域名对外可解析出至少一个 IP。不与公网 IP 做对比。
- **token 依赖级联**：#9 / #10 / #11 都依赖 token 构造路径与 URL。若 #8 无法读到合法 token，则 #9 / #10 / #11 直接 **FAIL** 并注明「token unavailable」（状态只有 pass/warn/fail，无 skip）。
- **配置校验（#6/#7）区分「未安装」与「非法」**：二进制不存在 → WARN（记为未安装，不阻断）；二进制存在但退出码非 0 → FAIL。

## 状态等级与退出码

三个状态：

```text
PASS
WARN
FAIL
```

整体状态与退出码：

```text
任一 FAIL         → unhealthy，退出码 1
无 FAIL 但有 WARN → degraded， 退出码 2
全部 PASS         → healthy，  退出码 0
参数或内部错误     → 退出码 3
```

## 默认超时（钉死，禁止实施方自行设计）

```text
单项 TCP connect：2 秒
DNS 查询：      3 秒
TLS handshake： 5 秒
HTTP 请求：     8 秒
命令执行：      10 秒
整体检查：      30 秒
```

（原「外部公网 IP 查询 5 秒」随该检查一起删除。）

## 并发

第一版不引入复杂任务池：

- 本地文件与配置检查串行。
- DNS、HTTPS、TLS 可并发。
- 最大并发固定为 4。
- 每个检查必须使用独立 `context.WithTimeout`。
- 所有 goroutine 必须能退出。
- **禁止无超时的网络调用。**
- 整体 30 秒上限由父 context 强制。各单项超时是上限而非预期耗时；整体 30 秒到时仍未完成的检查记为 **FAIL**（`message: timeout`），据此照常计算整体状态与退出码（通常落到 unhealthy / 退出码 1，而非内部错误 3）。

## JSON 输出

字段必须稳定，方便后续监控消费：

```json
{
  "status": "degraded",
  "timestamp": "2026-08-01T15:44:00+08:00",
  "duration_ms": 842,
  "checks": [
    {
      "id": "service.singbox",
      "name": "sing-box service",
      "status": "pass",
      "message": "active",
      "duration_ms": 12
    }
  ],
  "summary": {
    "passed": 14,
    "warnings": 1,
    "failed": 0
  }
}
```

稳定的 check `id` 命名（供监控按 id 订阅）：

```text
service.singbox      service.caddy
port.udp443          port.tcp443        port.tcp80
config.singbox       config.caddy
subscription.token   subscription.clash subscription.sr
http.subscription    tls.certificate    tls.expiry
dns.resolve          disk.space
```

**敏感数据铁律**：不把密码、OBFS 密码、订阅 token、完整订阅 URL 写入任何输出或日志。

## 配置来源

健康检查不能要求用户重复输入域名。优先顺序：

1. **`--domain` flag**（显式覆盖，最高优先）。
2. **状态文件** `/etc/singbox-sub-manager/install.json`。
3. **回退**：从 `/etc/caddy/Caddyfile` 推导域名（解析首个站点块的域名）。

v0.4 顺手让 `install-proxy.sh` 在安装/更新时写入 `install.json`（真实路径）：

```json
{
  "domain": "sub.example.com",
  "singbox_config": "/etc/sing-box/config.json",
  "caddy_config": "/etc/caddy/Caddyfile",
  "subscription_root": "/var/www/proxy-sub",
  "token_file": "/var/lib/singbox-sub-manager/token"
}
```

- 写入用原子方式（临时文件 → rename），权限 `0644`（不含敏感数据）。
- 对**已安装、无 install.json** 的机器，health 必须能仅凭 Caddyfile 回退 + 固定路径常量正常工作。

### 已核实的真实路径（实施基线）

| 项 | 真实值 |
|---|---|
| sing-box 配置 | `/etc/sing-box/config.json` |
| Caddy 配置 | `/etc/caddy/Caddyfile` |
| 订阅根目录 | `/var/www/proxy-sub` |
| 订阅文件 | `/var/www/proxy-sub/<token>/clash.yaml`、`.../sr.txt` |
| token 文件 | `/var/lib/singbox-sub-manager/token`（旧 `/etc/proxy-sub-token` 仅回退） |
| 订阅 URL | `https://<domain>/<token>/clash.yaml`、`.../sr.txt` |
| install.json | `/etc/singbox-sub-manager/install.json` |

## 工程结构

```text
internal/health/
├── check.go          // Check 接口、Config 结构、Status 常量
├── runner.go         // 调度：串行本地 + 并发网络（max 4）、整体 30s、结果聚合
├── result.go         // Result 类型、整体状态与退出码计算
├── service.go        // #1 #2  服务检查（经 CommandRunner）
├── port.go           // #3 #4 #5 UDP/TCP 端口
├── config.go         // #6 #7  sing-box/caddy 配置校验（经 CommandRunner）
├── subscription.go   // #8 #9 #10 token、clash.yaml、sr.txt
├── tls.go            // #11 #12 #13 loopback HTTPS + TLS + 证书到期
├── dns.go            // #14 DNS 解析
├── disk.go           // #15 statfs
└── render.go         // 文本 + JSON 渲染
```

CLI 侧：`cmd/proxyctl/health.go`（`cmdHealth`，解析 `--json` / `--verbose` / `--domain`），`main.go` 增加 `case "health"`。

### 接口

```go
type Check interface {
    ID() string
    Name() string
    Run(ctx context.Context, cfg Config) Result
}
```

结果类型：

```go
type Status string

const (
    StatusPass Status = "pass"
    StatusWarn Status = "warn"
    StatusFail Status = "fail"
)

type Result struct {
    ID         string `json:"id"`
    Name       string `json:"name"`
    Status     Status `json:"status"`
    Message    string `json:"message"`
    DurationMS int64  `json:"duration_ms"`
}
```

外部命令（`systemctl` / `sing-box` / `caddy`）经 `CommandRunner` 接口调用，便于 mock：

```go
type CommandRunner interface {
    Run(ctx context.Context, name string, args ...string) (stdout string, exitCode int, err error)
}
```

`Config` 承载域名、各路径、token、超时集合与 `CommandRunner`，供所有检查注入（生产用真实实现，测试用 mock/临时路径）。

## 测试要求（实施计划必须明确要求）

- 每个检查至少覆盖：成功、失败、超时三种。
- HTTP 用 `httptest.Server`（含 TLS 变体）。
- TLS 用测试证书（自签，测「域名匹配」「即将过期」「已过期」）。
- TCP 用临时监听端口（`net.Listen` 取随机端口）。
- 文件检查用 `t.TempDir()`。
- `systemctl` / `sing-box` / `caddy` 一律经 `CommandRunner` mock。
- **禁止单元测试依赖真实 systemd、Caddy、公网或 GitHub。**
- 输出做快照或结构化字段断言（文本 + JSON）。
- 断言错误信息**不泄漏** token 与密码。
- CI gate：`go test ./...`、`go test -race ./...`、`go vet ./...`、`gofmt`、`shellcheck`（沿用现有 smoke gate）。
- 环境约束：本机 `go` 不在 PATH，所有 Go 命令在 `golang:1.22` 容器内跑，例如
  `docker run --rm -v "$PWD":/w -w /w golang:1.22 go test ./...`。

## Review gate（Gemini 实施后，Claude review 重点）

1. 是否所有网络调用都有超时。
2. 是否可能 goroutine 泄漏。
3. 是否错误地把 UDP socket 存在当成 HY2 可用（本版只声称「端口监听」，不得暗示节点可用）。
4. 是否把 warning 当成失败（或反之）。
5. 是否泄露订阅 token 或密码或完整订阅 URL。
6. 是否通过 shell 拼接用户输入（必须走 `CommandRunner`，参数化，不拼 shell）。
7. 是否依赖具体语言/locale 的 `systemctl` 输出（应判 `active` 子串而非整串本地化文案）。
8. JSON schema 是否稳定（id 命名、字段齐全）。
9. 测试是否偷偷依赖本机环境。
10. 是否擅自加入自动修复或自动禁用。

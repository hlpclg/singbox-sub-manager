## 1. 背景与目标

v0.7 的恢复路径按逐级 `Lstat` 拒绝符号链接分量，然后仍以完整路径调用 `os.Mkdir`、`os.CreateTemp`、`os.Rename`、`os.Remove`。校验与写入之间存在 TOCTOU 窗口：若在该窗口内把某个中间目录替换成指向根外的符号链接，root 权限下的恢复会写到 `DestRoot` 之外，且命令报告成功（v0.7 Task 2 终审 F1 的残留部分，见该 Task 的「未解决风险」）。

v0.7.1 的目标是把这类攻击从「依赖时序的检测」改为「结构上不跟随」，并如实界定 fd 方案**做不到**的部分，而不是笼统宣称写入必然落在根内。

## 2. 非目标

- 不改任何 CLI 行为、输出、退出码或归档格式。
- 不改 `install-proxy.sh` 的升级/回滚逻辑（它替换的是自己的二进制，不属于 `internal/backup` 的写入链路）。
- 不引入新的用户可见命令或选项。
- 不试图防御「能在可信根之下重命名、替换或创建目录项」的攻击者。对这类攻击者只做尽力检测（第 6.5 节），不承诺阻断（第 3.3 节）。
- 不改变可信根自身的解析方式（第 3.1 节）：可信根及其祖先仍允许是符号链接。
- 不并入 v0.7 Task 1 遗留的「`--out` 落在备份源树内时拒绝」逻辑。

## 3. 信任边界、威胁模型与保证

### 3.1 可信根

以下路径由调用方给出，视为可信输入，**按现状跟随符号链接解析**，其自身及祖先允许是符号链接：

| 可信根 | 来源 | v0.7 的解析方式（保持不变） |
|---|---|---|
| `DestRoot` | 恢复/回滚目标根，生产为 `/` | 按路径拼接 |
| `SnapshotRoot` | 恢复前映像根，生产为 `/var/lib/singbox-sub-manager/restore-snapshots` | `MkdirAll` + `Chmod`，均跟随符号链接 |
| `BackupDir` | 自动命名归档目录，生产为 `/var/lib/singbox-sub-manager/backups` | `MkdirAll` + `Chmod`，均跟随符号链接 |
| `--out` 的父目录 | 用户指定的归档输出位置 | `CreateTemp(父目录)` 跟随符号链接；末级 `Rename` 不跟随 |

可信根只被打开一次，得到根目录 fd。**本包在可信根之下**创建、替换、删除、读取的每一个名字，都从根 fd 起逐级以 `O_NOFOLLOW` 解析，不再按路径重新解析。

### 3.2 攻击者模型

- 防御对象：在可信根之下，把某个中间目录分量或末级分量替换成符号链接；在我们创建目录之后、设置权限之前替换该目录项。
- 利用门槛：需要对 `/etc/singbox-sub-manager`、`/etc/sing-box`、`/etc/caddy`、`/var/lib/singbox-sub-manager` 等 root 属主目录有写权限。

### 3.3 保证与安全前提

**无前提成立的保证**（由结构保证，测试可证伪）：

1. 可信根之下的任何符号链接——无论在校验前已存在，还是在打开、创建、设权限的任意时点被替换进来——都不会被跟随。
2. 可信根之下的每个名字都相对「从根 fd 逐级打开得到的目录 fd」解析，不会经由被替换的路径重新解析。
3. 权限与属主只作用于本包已打开的 fd，绝不按名字作用于可能已被替换的目录项。
4. 失败清理（第 6.7 节）从不递归删除、从不跟随符号链接，因此非空目录不会被失败清理删除。

**检测能力（不是保证）**：

- 若某个已打开的目录在「打开之后、第 6.5 节祖先链复核之前」被移出可信根或被替换，**且复核执行时该变化仍可观察到**，复核会发现并使操作以 `ErrUnsafePath` 失败，不执行后续的创建、替换、删除或读取。
- 发生在复核完成之后、变更系统调用之前的移动不在检测范围内；复核前被移出又移回的目录也观察不到。上述情况只由下文的安全前提覆盖。

**需要安全前提才成立的保证**：

> A. 写入与删除始终落在可信根之内。
> B. 新建目录的设权限与清理作用于本次创建的那个目录。
> C. 失败清理只删除本次操作创建的产物。

A 的依据：fd 绑定的是 inode 而不是路径。一旦子目录被打开，拥有其父目录写权限的攻击者可以把该目录整体 `rename` 到可信根之外，此后相对该 fd 的写入仍会成功，并落在根外——这是 `openat` 的既定语义，没有可移植的原语能在变更系统调用的同一时刻保证「该 fd 仍在根内」。第 6.5 节的复核只能把窗口收窄到「复核完成」与「变更系统调用」之间，无法消除。

B 的依据：没有可移植的原语能原子地「创建目录并返回其 fd」。`Mkdirat` 与随后的 `Openat` 之间，攻击者可以把新建目录移走并换入另一个真实目录，打开、祖先链复核、`Fchmod` 和清理前的身份比对都会通过，因为记录下来的身份本身就是替换对象（第 6.3 节）。

C 的依据：失败清理不经祖先链复核（第 6.7 节）；删除前的身份比对与 `Unlinkat` 之间仍可替换；B 不成立时，被换入的空目录会被当作本次新建目录删除。

因此本版本明确要求以下**安全前提**，并在 README 之外的运维与安全文档中写明：

> 从可信根到每个目标文件之间的所有目录，不得被不可信主体重命名、移动、替换或写入目录项（即不可信主体对这些目录没有写权限）。

生产布局满足该前提：这些目录均为 root 属主，默认权限不允许其他用户写入。前提被破坏时，本版本只提供第 3.3 节的无前提保证 1–4 与上述范围受限的检测能力，不提供 A、B、C。

## 4. 受影响路径与操作清单

| 路径 | 可信根 | 当前实现 | 需改为 fd 相对的操作 |
|---|---|---|---|
| `Create`（归档打包） | 源侧 `SourceRoot`；输出侧 `BackupDir` 或 `--out` 父目录 | `filepath.WalkDir` 遍历；`readPayload` 以 `O_NOFOLLOW\|O_NONBLOCK` 打开末级；`O_EXCL` 保留归档名；`CreateTemp` + `Rename` 发布 | 源侧：目录遍历、源文件读取；输出侧：归档名保留、暂存文件创建、`rename` 发布、父目录 `fsync`、失败时删除保留名与暂存文件 |
| `Restore`（恢复） | `DestRoot` | `resolveUnderRoot` + `ensureParentDir` + `os.CreateTemp` + `os.Rename` | 父目录逐级创建、暂存文件创建、`fchmod`/`fchown`、`rename` 发布、父目录 `fsync`、失败时删除暂存文件与本次新建目录 |
| `CaptureSnapshot`（恢复前映像） | 读取侧 `DestRoot`；写入侧 `SnapshotRoot` | `os.Lstat` 目标 + `readPayload`；`os.Mkdir`/`os.Chmod` 事务目录；`writeFileAtomic` 写 payload 与元数据 | 读取侧：目标类型复核与读取；写入侧：事务目录创建与设权限、payload 与元数据的创建与替换、失败时删除事务目录 |
| `Rollback`（回滚） | 读取侧 `SnapshotRoot`；写入侧 `DestRoot` | `resolveUnderRoot` + `writeFileAtomic` + `os.Remove` | 目标文件替换、`Exists=false` 目标的删除、父目录 `fsync` |

三类操作全部覆盖：**创建**（含父目录逐级创建与设权限）、**替换**（暂存 + rename）、**删除**（回滚删除与失败清理）；读取路径同样纳入。`PruneSnapshots` 与 `CleanupSnapshot` 在 `SnapshotRoot` 之下删除事务目录，按同一机制处理。

## 5. 保持不变的契约

以下全部不变，任何改动都视为超范围。清单按当前 main（含 PR #7）的导出面核对：

- 导出函数：`Create`、`Verify`、`ReadManifest`、`Restore`、`Rollback`、`CaptureSnapshot`、`CleanupSnapshot`、`PruneSnapshots`、`LoadSnapshot`、`AcquireWithRetry`、`IsArchiveName`、`ValidateLogicalPath`，以及 `Manifest.Validate` 和各类型的 JSON 编解码方法。
- 结构体与字段：`Manifest`、`FileEntry`、`CreateOptions`、`Result`、`FileDiff`、`RestoreOptions`、`RollbackSnapshot`、`SnapshotEntry`、`CaptureOptions`、`RollbackOptions`、`RollbackResult`；接口 `Locker`、`LockLease`。
- 错误哨兵（7 个）：`ErrUnsafePath`、`ErrChecksumMismatch`、`ErrArchiveContentMismatch`、`ErrArchiveFormat`、`ErrUnsupportedSchema`、`ErrUnsupportedSourceType`、`ErrLockBusy`。
- 失败原因常量：`FailStaging`、`FailPublish`、`FailCanceled`、`FailDeadlineExceeded`、`FailNotAttempted`、`FailStagedDiscarded`、`FailUnsafePath`、`FailReadSnapshot`、`FailWrite`、`FailDelete`；跳过原因 `SkipNotFound`、`SkipUnsupportedSourceType`、`SkipEmptyDirectory`；预览动作 `ActionCreate`、`ActionOverwrite`、`ActionUnchanged`。
- 归档格式、`manifest.json` 字段与 `schema_version`；快照目录结构与 `snapshot.json`。
- 权限模型：备份目录 `0700`、归档 `0600`、快照根与事务目录 `0700`、快照文件 `0600`、恢复新建父目录 `0755`，均显式设置、与 umask 无关；恢复的文件按清单记录的 Mode/UID/GID 还原。
- 退出码与 CLI 输出：`cmd/proxyctl` 不改。
- 错误分类的对外结果（第 6.4 节保持一致）：
  - 可信根之下的**符号链接父目录** → `ErrUnsafePath`（`Restore`/`Rollback` 中为 `FailUnsafePath`）。
  - 可信根之下的**普通文件充当父目录** → 保持 v0.7 的非安全类错误：`Restore` 为 `FailStaging`，`Rollback` 为 `FailWrite`，`CaptureSnapshot` 与预览为普通 I/O 错误。
- 可信根自身及其祖先为符号链接时照常工作（第 3.1 节）。

## 6. 实现方案

### 6.1 依赖与平台

- `golang.org/x/sys/unix` 由间接依赖提为直接依赖。2026-09-12 在 Go 1.22 容器内以 v0.25.0（当前 `go.sum` 中的版本）交叉编译实测，`GOOS=linux` 与 `GOOS=darwin` 下均提供 `Openat`、`Mkdirat`、`Renameat`、`Unlinkat`、`Fstatat`、`Fsync`、`Fchmodat`、`Fchownat` 及 `O_NOFOLLOW`/`O_DIRECTORY`/`O_CLOEXEC`/`AT_SYMLINK_NOFOLLOW`。本设计另需的 `Fstat`、`Fchmod`、`Fchown`、`AT_REMOVEDIR` 尚未纳入该次探针（修订时 Docker 不可用），由第一个 Task 的 `GOOS=darwin go build ./...` 与 Linux 构建门禁确认；任一缺失须停止实施并回到设计修订。
- 保留 Linux 与 Darwin 编译支持，不引入 build tag 分叉。标准库 `syscall` 在 darwin 上没有 `*at` 家族（已实测），这是引入 `x/sys/unix` 的原因。
- 门禁增加 `GOOS=darwin go build ./...`。安全行为测试以 Linux（生产平台）为准，在 Go 1.22 容器执行。

### 6.2 可信根的打开

- `openTrustedRoot(path, create bool, mode)`：按现状解析可信根——需要创建时沿用跟随符号链接的 `MkdirAll`，随后以跟随符号链接的方式打开为目录 fd，并对**该 fd** 执行 `Fchmod`（替代现有的按路径 `Chmod`，目标与 v0.7 相同，但不再有按名字的二次解析）。
- `--out` 的可信根是其父目录；末级名字在父目录 fd 下操作。
- 根 fd 在整个操作期间持有，所有路径必须配对 `Close`。

### 6.3 根下逐级打开与目录创建

- 逐级解析：对每个分量调用 `Openat(dirfd, name, O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC)`。
- 目录创建按用途区分 mode 与既有目录策略，**不存在统一的默认 mode**。调用方必须显式给出下表中的一行：

| 目录 | 创建者 | mode | 目录已存在时 | 本次新建时是否 `Fchmod` | 失败时清理责任 |
|---|---|---|---|---|---|
| `DestRoot` 之下的父目录（恢复） | `Restore` | `0755` | 视为既有目录：继续使用，**不 `Fchmod`、不改属主** | 是 | 失败清理：逆序删除本次记录为新建的空目录（第 6.7 节）；`EEXIST` 的目录项不进入清理列表 |
| `DestRoot` 之下的父目录（回滚） | `Rollback` | `0755` | 同上 | 是 | 不清理（与 v0.7 一致：回滚路径丢弃新建目录列表） |
| 快照事务目录 `SnapshotRoot/<txid>` | `CaptureSnapshot` | `0700` | **报错**：必须是本次新建（与 v0.7 的 `os.Mkdir` 语义一致），不复用、不改权限、不删除该既有目录 | 是 | 失败清理：按记录删除本次写入的 payload、元数据与暂存文件，再删除事务目录本身，不递归（第 6.7 节） |
| 可信根 `SnapshotRoot`、`BackupDir` | 第 6.2 节 | `0700` | 按第 6.2 节处理（与 v0.7 一致：对根 fd 执行 `Fchmod`） | 是 | 不清理 |
| `--out` 的父目录 | 调用方 | — | 不创建、不改权限（与 v0.7 一致） | — | 不清理 |

- 「本次新建」的判定依据是 `Mkdirat` 本次调用返回成功；`Mkdirat` 返回 `EEXIST` 一律视为既有目录项（可能是先前存在的目录，也可能是并发创建的目录、文件或符号链接），随后仍须经第 2 步 `Openat(O_NOFOLLOW|O_DIRECTORY)` 打开并按第 6.4 节分类，且不进入 `Fchmod` 与清理列表。
- **`Mkdirat` 成功不等于后续 fd 指向本次创建的目录。** 第 1 步与第 2 步之间，攻击者可把新建目录移走并换入另一个真实目录：第 2 步打开的是替换目录，第 3 步复核通过（父目录链未变），第 4 步 `Fchmod` 与第 6.7 节清理前的身份比对都作用于替换目录（记录的身份就是它）。本设计不声称能识别这种替换，**本次创建对象的身份在该窗口内无法保证**，归入第 3.3 节安全前提 B。仍然成立的是：替换对象位于可信根之内；不跟随符号链接；失败清理不递归，非空的替换目录不会被删除。
- 本次新建目录的步骤顺序固定为：
  1. `Mkdirat(dirfd, name, mode)`，`mode` 取自上表；
  2. `Openat(dirfd, name, O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC)` 打开该目录；
  3. 第 6.5 节祖先链复核（此时链上包含新目录）；
  4. 对第 2 步得到的 **fd** 执行 `Fchmod(fd, mode)`，消除 umask 影响。目录不改属主（与 v0.7 一致）。
- **禁止**任何按名字设置权限或属主的调用，包括 `Fchmodat(dirfd, name, …)`、`Fchownat(dirfd, name, …)`、`os.Chmod`、`os.Chown`。理由：`Fchmodat` 按名字解析，第 1 步与第 4 步之间把目录项换成符号链接，会修改根外目标的权限（审查已复现）。经典 `fchmodat` 系统调用不实现 `AT_SYMLINK_NOFOLLOW`；支持它的 `fchmodat2` 需要 Linux 6.6 及以上（依据 `fchmodat(2)`），而受支持的 Ubuntu 22.04 使用 5.15 内核，因此不能依赖任何按名字的安全形式。
- 文件同理：暂存文件以 `Openat(dirfd, tmp, O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW|O_CLOEXEC, mode)` 创建，`O_EXCL` 保证是本包新建的 inode，之后 `Fchmod`/`Fchown`/`Write`/`Fsync` 全部作用于该 fd；文件的 mode 与属主按清单或第 5 节权限模型给出。
- 第 2 步若因替换失败，按第 6.4 节分类，不回退到按名字操作。此时该名字下的目录项可能已不是本次新建的目录，**不再按名字清理它**，在错误中注明该路径需人工确认；此前已新建且仍持有 fd 的目录照常按上表清理责任处理（第 6.7 节）。

### 6.4 错误分类

`Openat(…, O_DIRECTORY|O_NOFOLLOW)` 遇到符号链接时，Linux 可能返回 `ELOOP`，也可能返回 `ENOTDIR`（依据审查所引 `fs/namei.c`）；普通文件充当父目录时同样返回 `ENOTDIR`。仅凭 errno 无法区分两种情况，因此统一按下表分类，分类结果不依赖具体内核返回哪个 errno：

| `Openat` 结果 | 追加动作 | 分类 |
|---|---|---|
| 成功 | — | 继续 |
| `ENOENT` | 需要创建时进入第 6.3 节创建流程；否则按「目标不存在」处理 | 保持 v0.7 语义 |
| `ELOOP` 或 `ENOTDIR` | `Fstatat(dirfd, name, AT_SYMLINK_NOFOLLOW)` | 见下四行 |
| └ 类型为符号链接 | — | `ErrUnsafePath` |
| └ 类型为普通文件、FIFO、套接字或设备 | — | v0.7 的「不是目录」非安全类错误（第 5 节） |
| └ 类型为目录，或 `Fstatat` 返回 `ENOENT` | 说明两次调用之间目录项已变化 | `ErrUnsafePath` |
| └ `Fstatat` 返回其他错误 | — | 包装为普通 I/O 错误 |
| 其他 errno | — | 包装为普通 I/O 错误，不归入 `ErrUnsafePath` |

分类逻辑集中在一个私有函数中，`Restore`、`Rollback`、`CaptureSnapshot`、`Create` 共用，避免各自映射出现漂移。

### 6.5 变更前祖先链复核（检测，非保证）

- 每次执行变更系统调用之前——`Openat(…O_CREAT…)`、`Renameat`、`Unlinkat`、`Mkdirat`、对目录 fd 的 `Fchmod`——以及 `CaptureSnapshot` 读取目标之前，从根 fd 起重新逐级 `Openat(O_NOFOLLOW|O_DIRECTORY)`，逐层比较新打开 fd 与所持 fd 的 `(st_dev, st_ino)`。**例外**：第 6.7 节定义的失败清理不执行复核。
- 单次操作的步骤顺序固定如下，三个测试 hook 的位置以此为准（第 7.1 节）：

  ```text
  逐级打开父目录链
    → hookAfterOpen            （复核之前）
    → 祖先链复核
    → hookBeforeMutation       （复核之后、系统调用之前）
    → 变更或读取系统调用（Openat O_CREAT / Renameat / Unlinkat / Mkdirat / Fchmod / Openat 读取）
  ```

  新建目录时，`Mkdirat` 之后另有 `hookAfterMkdirat`（打开新目录之前），随后按第 6.3 节第 2–4 步继续，第 4 步 `Fchmod` 前再次经过「复核 → `hookBeforeMutation`」。
- hook 仅供测试注入，生产构建中为空操作，沿用 v0.7 `writeArchiveFn`、`publishFileFn` 的包内 seam 先例。
- 任一层不一致、缺失或打开失败，操作以 `ErrUnsafePath` 失败；本次已创建的产物按第 6.7 节失败清理处理（不经复核）。
- 该复核能发现「打开之后、复核之前」被移出根或被替换的目录，但无法覆盖「复核之后、变更系统调用之前」的窗口。文档、注释与测试命名均不得把它表述为保证，第 3.3 节的安全前提仍是「始终在根内」成立的唯一依据。
- 成本：生产路径集深度不超过 4 层、文件数为个位数，额外的逐级打开可忽略。

### 6.6 各操作的替换

- 发布：`Renameat(parent, tmp, parent, base)`，随后 `Fsync(parentFd)` 替代现有 `syncDir`。
- 有意删除（`Rollback` 对 `Exists=false` 目标的删除、`CleanupSnapshot`、`PruneSnapshots`）：执行第 6.5 节复核后 `Unlinkat(parent, base, 0)`，随后 `Fsync(parentFd)`。删除事务目录时按目录 fd 枚举条目、逐项 `Unlinkat`，子目录经 `Openat(O_NOFOLLOW|O_DIRECTORY)` 递归、不跟随符号链接，最后 `AT_REMOVEDIR`，以保持 v0.7 `RemoveAll` 的结果。这些删除不属于第 6.7 节的失败清理。
- 类型与属主复核：`Fstatat(parent, base, AT_SYMLINK_NOFOLLOW)` 替代 `os.Lstat`。
- 读取：`Openat(parent, base, O_RDONLY|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC)` 后 `Fstat` 复核类型与 `Nlink`，与 v0.7 的 `readPayload` 语义一致。
- 归档源遍历：`Create` 的递归树改为按目录 fd 递归（`Openat` 子目录 + 读取目录项），跳过规则与稳定原因不变。
- 归档输出：保留名 `Openat(outDir, name, O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW)`；暂存与发布相对输出目录 fd；失败时 `Unlinkat` 删除保留名与暂存文件。`--out` 覆盖既有文件时的「不删除调用方文件」语义不变。
- `resolveUnderRoot`、`checkParentChain`、`ensureParentDir` 中基于路径的防御在改造完成后删除，避免留下第二套会漂移的实现；`ValidateLogicalPath` 的纯字符串校验保留（第一道边界，且被清单校验复用）。

### 6.7 失败与清理

**适用对象**。失败清理只针对本次操作记录为自己创建的产物：

- `Restore`、`Rollback`、`CaptureSnapshot` 以 `O_CREAT|O_EXCL` 与随机名创建的暂存文件；
- `Create` 以 `O_EXCL` 保留的归档名与归档暂存文件；
- 第 6.3 节 `Mkdirat` 本次成功并已记录的目录（`Restore` 与快照事务目录；`Rollback` 不清理新建目录，与 v0.7 一致）；
- 快照事务目录中本次写入的 payload 与 `snapshot.json`。

有意删除（第 6.6 节）不属于失败清理，照常执行第 6.5 节复核。

**不经复核的例外**。失败清理不执行第 6.5 节祖先链复核，直接相对创建该产物时所持的父目录 fd 执行。理由：清理往往正因复核失败而触发（例如 T1-写），若要求复核，本次创建的临时产物将无法清理；清理对象是本次以 `O_EXCL` 或随机名创建的产物。

**方法**。

- 文件：`Unlinkat(parentFd, name, 0)`。
- 目录：`Unlinkat(parentFd, name, AT_REMOVEDIR)`，只删除空目录，从不枚举目录内容，从不递归。
- 快照事务目录：先按记录逐项删除本次写入的条目，再对事务目录本身执行 `AT_REMOVEDIR`；目录中存在未记录的条目时删除失败并报告。
- 顺序：按创建的逆序。两阶段写入顺序不变：全部暂存并 `Fsync` 成功后才逐个 `Renameat`。取消与超时检查点位置不变。

**身份比对（尽力检测，不是保证）**。删除前以 `Fstatat(parentFd, name, AT_SYMLINK_NOFOLLOW)` 取得目录项的 `(st_dev, st_ino)`，与所持该产物 fd 的 `Fstat` 结果比对；不一致则跳过，并在错误中注明该路径需人工确认。比对与 `Unlinkat` 之间仍可能被替换；新建目录的身份在第 6.3 节所述窗口内本就无法保证，此时比对的对象可能已是替换目录。

**结构性保证**（无前提，对应第 3.3 节保证 4）：失败清理从不递归删除，也不跟随符号链接（`Unlinkat` 作用于目录项本身），因此非空目录不会被失败清理删除。

**风险**（归入第 3.3 节安全前提 C）：

- 父目录已被移出可信根时，失败清理作用于根外的该父目录，删除其中与本次产物同名的对象。
- 身份比对与删除之间换入的同名文件或同名空目录可能被删除；换入的同名符号链接只会删除链接本身，不会作用于其目标。
- 在 `Mkdirat` 与 `Openat` 之间被换入、且此后保持为空的真实目录，会被当作本次新建目录删除。

## 7. 测试与验收

- 目录权限与清理责任沿用 v0.7 既有测试作为回归：`TestRestore_StagingFailureRemovesDirectoriesItCreated`（不删除非本次创建的目录）、`TestRestore_CreatesParentDirectoriesIndependentlyOfUmask`（新建父目录为 `0755`）、`TestCaptureSnapshot_RecordsExistingAndMissingPaths`（快照目录 `0700`）、`TestCreate_DirAndArchivePermissions`（备份目录 `0700`）。
- T1–T4、T7、T8 在 Go 1.22 Linux 容器内执行并以其结果为准；T4 必须在 Linux 上实际覆盖 `ELOOP` 与 `ENOTDIR` 两种返回（若某一内核版本只产生其中一种，测试需记录实际观测到的 errno，并以直接构造的错误值补测另一分支）。
- 修订本设计时 Docker 不可用，第 6.4 节关于 Linux errno 的描述依据 `open(2)`、`fchmodat(2)` 与 `fs/namei.c`；Linux 容器实测结果在实施计划的 T3/T4 证据中回填，结论若与本节不符须停止实施并回到设计修订。

- 每条测试的变异验证在实施计划中逐条记录：变异补丁、失败的测试名与失败输出、还原后的通过输出。

## 9. 已决问题与残留风险

已决：

1. **归档输出路径**：`BackupDir` 与 `--out` 的父目录属于可信根，按现状跟随符号链接解析；本包只在其下的名字（保留名、暂存文件、发布、失败清理）使用 fd 相对操作。不从 `/` 起逐级拒绝符号链接，避免用户可见变化（第 3.1 节、T5）。
2. **`--out` 落在备份源树内**：不并入本版本（第 2 节）。
3. **源码级检查白名单**：边界在实施计划中固化（第 7.2 节）。

残留风险（发布后仍存在，须在实施计划记录）：

- 拥有可信根之下目录写权限的主体，可在「祖先链复核完成」与「变更系统调用」之间把目录移出可信根，使写入或删除落在根外。无可移植原语可以消除，仅由第 3.3 节安全前提覆盖。
- 可信根自身及其祖先被替换不在防御范围内（第 3.1 节）。
- `Mkdirat` 与后续 `Openat` 之间换入的真实目录无法识别：本包会对其设权限，并可能在其保持为空时将其作为本次新建目录清理（第 6.3 节，安全前提 B）。
- 失败清理不经复核：父目录被移出可信根时清理作用于根外；身份比对与删除之间的替换无法排除（第 6.7 节，安全前提 C）。

# v0.3 节点管理 — 设计文档

- 日期：2026-08-01
- 版本目标：v0.3.0
- 范围：`proxyctl` 节点管理（增删改查 + 启用/禁用 + 迁移）。健康检查（`health`/`diagnose`/`repair`）不在本版，留到 v0.4。

## 背景

当前 v0.2.2 状态：

- `nodes.conf` 为竖线单行格式：`NAME|SERVER|PORT|PASSWORD|OBFS_PASSWORD|SNI`，由管理员手动编辑。
- `proxyctl` 只有三个命令 `merge` / `validate` / `version`，且只**读** `nodes.conf`。
- 仅支持 Hysteria2，`merge` 生成 `clash.yaml` + `sr.txt`，由 `merge-nodes.sh` 编排（下载校验 proxyctl、写 Caddy 目录、修权限）。
- `plan.md` Phase 2 曾设想每节点一个 `.env` 目录，但实现走的是单文件竖线格式——本设计以实际实现为基线。

痛点：手改单行竖线文件易出错，且格式里**没有** `ENABLED` 字段，无法支持启用/禁用。

## 目标

让 `proxyctl` 能安全地读写节点配置，提供节点增删改查与启用/禁用，消除手改文件的风险，并为后续健康检查提供干净的节点数据模型与读写层。

## 非目标

- 健康检查 / 诊断 / 自动修复（v0.4）。
- 地区分组、多策略组等订阅增强（后续版本）。
- 多协议（VLESS Reality / TUIC 等，v0.5+）。
- `REGION` / `TAG` 等元数据字段——真正做「地区分组」时再按需加。

## 设计决策记录

| 决策点 | 选择 | 理由 |
|---|---|---|
| v0.3 范围 | 只做节点管理，健康检查分开到 v0.4 | 两块独立；节点管理是健康检查的地基 |
| 存储格式 | 扩展单文件为分节 key=value | 单文件好备份/看全貌、迁移最轻、天然容纳新字段 |
| add/edit 输入 | flag 为主，缺字段在 TTY 下追问 | 可脚本、可测试；密码交互输入不进 shell 历史 |
| 字段集 | 现有 6 字段 + `ENABLED`（最小集） | YAGNI；分节格式将来加字段零成本 |
| 改完是否自动重建订阅 | 否，显式 `subscription build` | mutation 与渲染解耦、批量改只重建一次、好测试 |
| 旧格式迁移 | 显式 `node migrate` 命令 | 迁移时机可控、显式 |

## 存储格式

路径：`/etc/singbox-sub-manager/nodes.conf`（可用 `--nodes` 覆盖，与现有一致）。

新分节格式，段名即节点名：

```ini
# 注释行、空行忽略
[JP-HY2]
SERVER=1.2.3.4
PORT=443
PASSWORD=xxx
OBFS_PASSWORD=yyy
SNI=www.bing.com
ENABLED=true
```

字段：

| 键 | 说明 | 约束 |
|---|---|---|
| （段名） | 节点名 | 非空；仅允许字母/数字/`-` `_` `.`；禁止 `[` `]` `=` `|`、空白、换行；文件内唯一 |
| `SERVER` | 服务器地址 | 非空 |
| `PORT` | 端口 | 1–65535 |
| `PASSWORD` | 密码 | 非空，禁止含 `CHANGE_ME` 占位符 |
| `OBFS_PASSWORD` | obfs 密码 | 非空，禁止含 `CHANGE_ME` |
| `SNI` | SNI | 非空 |
| `ENABLED` | 是否启用 | `true` / `false`；缺省视为 `true` |

## 数据模型

`internal/nodes/nodes.go` 的 `Node` 增加字段：

```go
type Node struct {
    Name         string
    Server       string
    Port         int
    Password     string
    ObfsPassword string
    SNI          string
    Enabled      bool // 新增
}
```

## 解析与写入

### 读（向后兼容）

解析器 `ParseFile` 同时识别两种格式：

- **旧竖线格式**：每行 6 字段 `NAME|SERVER|PORT|PASSWORD|OBFS_PASSWORD|SNI`，`Enabled` 默认 `true`。保证旧部署升级后 `merge`/`validate` 照常工作。
- **新分节格式**：`[name]` 段 + key=value。

格式判定：跳过空行/注释后，看第一条有效内容——以 `[` 开头判为新格式，含 `|` 判为旧格式。混用报错。

沿用现有校验：端口范围、字段非空、节点名查重、`CHANGE_ME` 占位符检测、空文件报「no nodes」。

### 写（仅新格式）

- 只有 `node` 系列命令（add/edit/remove/enable/disable/migrate）写文件。
- 统一输出新分节格式，字段顺序固定（便于 diff 与幂等）。
- **原子写**：写临时文件 → `chmod 0600` → `rename` 覆盖。
- 写前把原文件备份为 `nodes.conf.bak`。
- 成品文件权限 `0600`（含明文密码）。

## 命令

CLI 路由在 `cmd/proxyctl/main.go` 增加 `node` 与 `subscription` 分发。

```
proxyctl node list
proxyctl node add    --name --server --port --password --obfs-password --sni [--enabled]
proxyctl node edit   <name> [--name --server --port --password --obfs-password --sni --enabled]
proxyctl node remove <name>
proxyctl node enable  <name>
proxyctl node disable <name>
proxyctl node migrate
proxyctl subscription build --nodes nodes.conf --output DIR   # merge 的别名
```

通用：所有命令接受 `--nodes`（默认 `/etc/singbox-sub-manager/nodes.conf`）。

### node list
表格输出：名称 / `server:port` / SNI / 启用状态。禁用节点也显示（标注 disabled）。

### node add
- 全 flag 提供时非交互创建。
- 校验：节点名合法且不重复；端口范围；必填非空；`CHANGE_ME` 拒绝。
- `--enabled` 默认 `true`。
- 写文件（原子 + 备份 + 0600）。

### node edit `<name>`
- 按现有名定位节点；只更新传入的 flag，其余保持不变。
- `--name` 可改名：新名做合法性 + 查重校验。
- 目标不存在报错。

### node remove `<name>`
- 删除该段；不存在报错。

### node enable / disable `<name>`
- 只翻转 `ENABLED`；节点保留在文件中；不存在报错。

### node migrate（显式迁移）
- 读旧竖线格式，写新分节格式，所有节点 `ENABLED=true`。
- 备份原文件到 `nodes.conf.bak`。
- 已是新格式则提示无需迁移并退出 0。

### 旧格式下的 mutation
- 若 `node add/edit/remove/enable/disable` 检测到文件仍是旧竖线格式，**拒绝执行**并提示：先运行 `proxyctl node migrate`。
- （因为迁移选择了「显式」而非「惰性」，mutation 不隐式改写格式。）

### 交互回退
- 给了对应 flag 就用其值。
- 缺必填字段且 stdin 是 TTY：逐项追问；密码类字段（`PASSWORD` / `OBFS_PASSWORD`）不回显。
- 非 TTY 且缺必填：直接报错退出，不阻塞。

### subscription build
- `merge` 的友好别名，复用同一套渲染逻辑。
- `merge` 命令保留（`merge-nodes.sh` 仍调用 `merge`，不破坏现有编排）。

## 启用/禁用在订阅生成中的语义

- `merge` / `subscription build` 生成 `clash.yaml` / `sr.txt` 时**只包含** `ENABLED=true` 的节点。
- 若可用（启用）节点数为 0，报错退出（沿用现有「no nodes」语义）。
- `validate` 同样只对启用节点做生成校验。

## 错误处理

- 所有校验失败：向 stderr 输出明确信息，非 0 退出。
- 文件写失败（临时文件/rename/权限）：报错并保证原文件不被破坏（原子写 + 备份）。
- mutation 命令要求 root/文件可写；权限不足给出清晰提示。

## 测试

`internal/nodes`（表驱动单测）：
- 旧竖线格式解析（含 `Enabled` 默认 true）
- 新分节格式解析
- 新旧混用报错
- 写回幂等（parse→write→parse 等价）
- 原子写与 0600 权限
- 节点名查重、非法字符拒绝
- edit 改名查重、部分字段更新
- migrate：旧→新、备份 `.bak`、已迁移的幂等
- 端口范围、`CHANGE_ME`、空字段校验

`cmd/proxyctl`：
- `node add/edit/remove/enable/disable/list` 各命令走 flag 路径（无 TTY，覆盖 CI）
- 旧格式下 mutation 被拒绝并提示 migrate
- `subscription build` 与 `merge` 等价
- 禁用节点被订阅生成排除

沿用现有 CI smoke gate（gofmt / go vet / go test / shellcheck）。

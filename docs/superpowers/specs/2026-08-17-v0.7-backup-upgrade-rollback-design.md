# v0.7 备份、升级与回滚 — 设计文档

- 日期：2026-08-17
- 版本目标：v0.7.0
- 状态：已批准，待实施
- 范围：为 `proxyctl` 引入统一的配置备份/恢复，以及 `install-proxy.sh` 升级/回滚的安全闭环。

## 1. 背景与目标

`install-proxy.sh` 目前只有局部、临时的备份逻辑（Caddy APT 源、单次 Caddyfile 写入前拷贝、sing-box 配置写入后健康检查失败回滚），没有面向用户的统一备份/恢复/升级命令，也没有覆盖节点配置（`nodes.conf`）、订阅 token、Hysteria2 密钥和 monitor 状态的整体快照。v0.6 完成后，下一步是补齐"变更安全"闭环：任何一次升级或误操作都能回到已知良好状态。

目标：

- 提供 `proxyctl backup` / `proxyctl restore`，覆盖单机全部持久化数据（节点配置、渲染出的订阅、Caddyfile、sing-box 配置、token、monitor 状态），可离线归档、可搬迁。
- 提供 `install-proxy.sh update`，在升级 `proxyctl` 二进制、sing-box、Caddy 或配置模板前自动创建备份点；升级后健康检查失败自动回滚到该备份点。
- 所有备份/恢复/升级/回滚步骤对齐 v0.6 的可测试性和原子性要求：确定性、可追溯、失败不破坏既有可用状态。

## 2. 非目标

v0.7 不包含：

- 远程/异地备份（S3、rsync 到第二台主机等）；本版本只做本机归档文件。
- 多协议（VLESS Reality/TUIC）配置的备份 schema 扩展；仍按现有 Hysteria2 + Caddy + monitor 数据面处理。
- 自动定时备份（systemd timer）；本版本命令均为用户手动触发。
- `proxyctl uninstall`／`--purge`；卸载留待后续版本。
- 备份文件加密；备份目录权限收紧到 `0600`/`0700` 即可，不引入密码学封装。

## 3. CLI 契约

新增：

```text
proxyctl backup [--out <path>] [--keep <n>]
proxyctl restore <archive-path> [--dry-run] [--no-restart]
proxyctl backup list
```

`install-proxy.sh` 新增子命令：

```text
sudo ./install-proxy.sh update
sudo ./install-proxy.sh rollback [--to <backup-id>]
```

- `proxyctl backup`：打包当前配置为单个归档，默认写入 `/var/lib/singbox-sub-manager/backups/<timestamp>.tar.gz`，`--out` 可指定其他路径（指定 `--out` 时不计入自动清理范围）。归档内含清单文件（版本号、时间戳、涉及路径、各文件 SHA-256）。写入 `backups/` 目录成功后按创建时间清理超出 `--keep`（默认 10，`0` 表示不清理）的最旧归档。
- `proxyctl restore`：校验归档清单和校验和后，将文件原子替换回原路径，随后对归档涉及的服务执行重启并复检；复检失败则回滚本次 restore。`--dry-run` 只打印将要变更的文件列表和差异摘要，不落盘、不重启。`--no-restart` 只落盘文件，不触发服务重启，由用户或下一轮 `monitor` 处理生效。
- `proxyctl backup list`：列出 `backups/` 目录下现有归档及其时间戳、大小、版本号。
- `install-proxy.sh update`：下载/校验新版本前调用 `proxyctl backup` 生成升级前快照，记录快照 ID；升级完成后跑既有健康检查，失败则自动执行等价于 `rollback --to <该快照>` 的流程。
- `install-proxy.sh rollback`：不带 `--to` 时回滚到最近一次成功快照；带 `--to` 时回滚到指定备份 ID。

退出码延续仓库既有约定：`0` 成功，非 `0` 明确区分参数错误、校验失败、部分失败（已恢复部分文件后中止）。

## 4. 备份范围与数据模型

单次备份归档必须包含（存在才打包，不存在的路径记入清单为"跳过"而非报错）：

```text
/etc/singbox-sub-manager/**          # 节点配置、渲染模板、示例
/etc/sing-box/config.json            # 当前生效的 sing-box 配置
/etc/caddy/Caddyfile                 # 当前生效的 Caddyfile
/var/lib/singbox-sub-manager/token   # 订阅 token
/var/lib/singbox-sub-manager/monitor-state.json
/var/lib/singbox-sub-manager/monitor-paused   # 存在性即可，内容为空
```

不包含：`backups/` 目录自身、日志文件、临时文件、systemd unit 文件本体（unit 文件由安装器幂等重装，不随配置漂移，v0.7 不纳入备份/恢复范围，仅在设计中记录该边界）。

归档清单（`manifest.json`）至少包含：

```json
{
  "schema_version": 1,
  "created_at": "2026-08-17T00:00:00Z",
  "proxyctl_version": "v0.6.0",
  "files": [
    {"path": "etc/sing-box/config.json", "sha256": "...", "mode": "0600"}
  ],
  "skipped": ["var/lib/singbox-sub-manager/monitor-paused"]
}
```

## 5. 原子性与失败处理

- 打包：先写入归档到同目录临时文件，`fsync` 后原子 `rename` 为最终文件名，避免半成品归档被误用。
- 恢复：对每个目标路径，先写临时文件到同目录并 `fsync`，全部成功后再逐一原子 `rename`；任一文件写入失败，已完成的 `rename` 不回退（v0.7 明确这是已知限制，恢复失败必须在输出中列出哪些路径已恢复、哪些未恢复，不得静默声称整体成功）。
- 恢复前校验：归档清单 SHA-256 必须与实际内容匹配，版本不兼容（`schema_version` 不支持）或校验失败时拒绝执行，不落盘任何文件。
- `install-proxy.sh update` 的自动回滚只允许恢复"升级前由本次 update 创建"的那一个会话，不允许静默选择任意历史快照，避免回滚到错误版本；该会话同时覆盖配置快照和升级前暂存的 `proxyctl` 旧二进制——健康检查失败必须把二进制和配置一起回滚，只回滚配置、留下有缺陷的新二进制不构成"回到已知可用状态"。
- 备份/恢复期间 monitor 若在运行，`restore` 必须先获取 monitor 的恢复锁（复用 v0.6 的 `FileLock`，通过有界重试封装等待，不直接调用非阻塞 `TryLock` 后放弃），避免恢复途中并发写状态文件；锁繁忙需在有界时间内明确失败，不无限等待。

## 6. 组件边界

- `internal/backup`：归档打包、清单生成与校验、恢复写入，均为可注入文件系统路径的纯函数式模块，不直接调用 `systemctl`。
- `cmd/proxyctl/backup.go`：CLI 参数解析、调用 `internal/backup`、格式化输出。
- `install-proxy.sh`：新增 `update`/`rollback` 子命令，编排"备份 → 执行升级步骤 → 健康检查 → 成功或回滚"，复用已有的下载、校验、健康检查函数。

## 7. 测试与验收（要点）

- 备份：包含全部存在路径、正确跳过缺失路径、清单校验和与实际内容一致、目标目录不可写时的失败路径。
- 恢复：校验和不匹配拒绝执行；`--dry-run` 不产生任何文件系统写入；部分失败时输出准确反映已恢复/未恢复集合。
- `update`/`rollback`：健康检查失败触发自动回滚且只回滚到本次升级前快照；无历史快照时 `rollback` 明确报错而非静默无操作。
- Shell 变更需执行 `shellcheck`；Go 变更需在 Go 1.22 容器执行 `go test -race -count=1 ./...`、`go vet ./...`、`gofmt -l .`。

## 8. 兼容与交付范围

- 不改变现有 `proxyctl health`/`monitor`/`node` 命令行为或 JSON schema。
- 现有 Ubuntu 22.04、Ubuntu 24.04、Debian 12 安装路径保持支持。
- 本设计已批准并回写 `plan.md` 当前实施基线，下一步形成任务级实施计划（拆分 Task、验收矩阵），不得跳过计划直接实施。

## 9. 已决问题

1. **备份保留策略**：`proxyctl backup` 默认保留最近 10 份，创建新备份成功后按创建时间清理最旧的多余归档；支持 `--keep <n>` 覆盖默认值，`--keep 0` 表示不自动清理。清理只删除自身创建的归档文件，不影响用户手动放入 `backups/` 目录之外的文件。
2. **update 的更新来源**：本版本做真自更新，不走"重跑安装脚本"。`install-proxy.sh update` 从 GitHub Release 下载对应架构的 `proxyctl-linux-{amd64,arm64}`，校验发布附带的 `checksums.txt` 中的 SHA-256，通过后原子替换本机 `proxyctl` 二进制；模板、Caddyfile、sing-box 配置等仍按现有渲染逻辑处理，不在本次二进制替换范围内。
3. **restore 后的服务处理**：`restore` 恢复受影响文件后自动对涉及的服务执行"重启 → 复检"（复用 v0.6 已有的 restart-then-recheck 模式和退出码约定）；复检失败则回滚本次 restore（用恢复前的备份点覆盖回去），不留半生效状态。若归档不含 sing-box/Caddy 配置（例如只恢复了节点配置文件），则不触发对应服务重启。

# 验证门禁

## 三级验证

- 聚焦测试：开发循环验证当前最小变化，不得称为完整门禁。
- Task 专项门禁：覆盖当前 Task 全部影响范围，交接前最多一次。
- 完整门禁：正式交付或合并前运行一次。

纯文档或流程变更可以复用仍有效的构建和测试证据，但必须记录基线、变更范围、证据时间、未受影响理由和省略命令。代码、测试、依赖、配置、迁移或生成物变化按影响范围补跑。

## 本仓库完整门禁

Go 命令在 Go 1.22 容器中执行：

```text
go test -race -count=1 ./...
go vet ./...
gofmt -l .
```

`gofmt -l .` 必须无输出。Shell 文件变化时执行对应 ShellCheck 和专项 Shell 测试；工具版本或安装来源必须与 CI 一致。CI 使用系统包时，不能用另一版本通过替代 CI 等价证据。

Git 门禁：

```text
git diff --check
git diff --cached --name-only
git status --short
git show --stat --oneline HEAD
```

## 报告格式

完成报告至少包含：比较基线、变更文件、实际运行命令、退出码或成功结论、首个失败根因、复用和省略的证据、主提交 SHA、状态封账提交和最终工作区状态。

不得使用以下替代关系：

- race 通过不能替代并发逻辑确定性测试。
- linter 通过不能替代构建或行为测试。
- 聚焦测试通过不能替代专项或完整门禁。
- 测试通过不能替代规格逐项核对。
